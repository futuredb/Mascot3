# Поведение героя — ТЗ v0.3, приложение 0.1.40

## Единый источник состояния

`BehaviorCoordinator → StateResolver → StateStore → главный экран / виджет`.
Resolver — чистая локальная функция. Платные модели и сервер генерации не
участвуют в выборе и воспроизведении готовых анимаций. Старый независимый выбор
погоды и отдельная ротация настроений виджета удалены.

В `filesDir/behavior/state-v3.json` атомарно сохраняются состояние, начало,
окончание, причина, приоритет, ревизия, герой, история повторов и cooldown,
ручной сон, смена сети, сеанс зарядки, история погоды, компактный снимок активности
и обработанные события. Перезапуск процесса не сбрасывает ручной сон и не
награждает повторно за ту же цель/тренировку/запись сна.

Приложение и виджет читают один record и используют одну функцию fallback:
запрошенное готовое видео → IDLE → последнее готовое → greeting → другое готовое.
Отсутствие ролика не подменяет семантическое состояние. Если готово только
приветствие, оно продолжает плавно повторяться как единственная доступная анимация.
Просмотр роликов в библиотеке — локальный предпросмотр, не отдельный resolver.

ТЗ одновременно задаёт отдельным утренним состояниям 10–20 минут и всем
базовым состояниям минимум 30 минут. Принята общая гарантия: **база ≥30 минут**,
а 10–20 минут применяется к отдельным контекстным реакциям. Для каждого состояния
есть конфиг длительности; базовый минимум сохраняется.

Обычный тап будит ручной сон и выбирает следующую допустимую базовую/редкую
анимацию, если нет более сильного актуального контекста. Свайп вверх даёт JOY,
но не отменяет ручной сон. В виджете тап только открывает приложение.

## Приоритеты

Ручной сон → свайп JOY → сильная погода → ночной/подтверждённый сон → дождь →
цель/конец тренировки/пробуждение → сеть/возврат активности → длительная
облачность/низкая активность → зарядка → облачность → приветствие → текущая
активность/достижение → временная база → редкая ротация → fallback.

Сильный контекст прерывает базу. Истекшая реакция возвращает управление resolver.
После двух повторов одной базы её вес снижается до 0.35, если есть альтернативы.
Сон не штрафуется. Веса временных окон сохранены из ТЗ; редкость по умолчанию 8%.

## Источники и ограничения платформы

- Время и день недели: часовой пояс устройства.
- Погода: бесплатный Open-Meteo; температура, облака, осадки, код погоды,
  скорость и порывы. Координаты текущего продукта — Москва. История накапливается
  из реальных наблюдений: нет подставных шести часов облачности после установки.
- Сеть: только тип подключения и доступность интернета, без SSID/IP/оператора.
  Дребезг отменяется при возврате к исходной сети.
- Зарядка: системный статус, один STRETCH за сеанс после задержки 5 минут.
- Health Connect 1.1.0: добровольное чтение только шагов, сна, тренировок.
  Только разрешённые типы; отказ, отсутствие провайдера и частичный доступ
  не мешают базовому поведению. Ошибка одного типа не удаляет другие данные.
- Шаги агрегируются через COUNT_TOTAL, чтобы не удваивать данные источников.
  Отсутствующие/разреженные записи не считаются нулевой активностью. Цель 8000
  шагов — настраиваемая игровая механика, не медицинская норма.
- Сон/тренировка «прямо сейчас» включаются только при реально доступном интервале,
  содержащем текущий момент. Health Connect не гарантирует live-сигнал: запись
  может появиться после окончания и синхронизации внешнего приложения/часов.
  Нельзя достоверно додумать живой сон из вчерашнего сна или отсутствия шагов.
- В фоне Health Connect читается только при поддержке отдельной возможности
  и отдельном согласии пользователя. Переключатель «Активность для виджета в фоне»
  по умолчанию выключен. Без него новые данные читаются при открытом приложении.
- Worker примерно раз в 30 минут; дополнительно события сети/зарядки, создание,
  открытие, жесты и истечение реакции. Пока приложение открыто, локальный таймер
  проверяет окончание состояния раз в секунду. Медленные внешние чтения не
  блокируют жесты. Приветствие/фирменное движение также сообщают resolver о
  реальной границе ролика, чтобы не начинать второй круг до смены состояния.
  Если greeting — единственное видео, его плавный повтор сохраняется как fallback.
  Неподвижное PNG-превью не запускает кадровый таймер; секвенции читают его в
  фазе рисования, без пересборки всего UI каждый кадр.
  Не используются частые wake-up alarms и отдельная кадровая
  ротация состояния в виджете.
- Android/лаунчер может отложить фоновые задачи и перерисовку виджета. Нельзя
  обещать покадровый видеоплеер или синхронную до миллисекунды смену на всех
  лаунчерах. Следующее обновление всегда читает сохранённое общее состояние.

## Настройка и приватность

Настройки → «Поведение героя»: флаги активности, игровая цель, явное разрешение
Health Connect, расширенный валидируемый локальный JSON. В нём регулируются веса,
редкость, длительности, cooldown, debounce, интервалы входа/обновления, пороги
погоды/шагов и допустимый возраст событий. Ошибочный JSON не заменяет правила.
Удалённый конфиг не требуется: ТЗ допускает локальный **или** удалённый вариант.

`events.jsonl` — ограниченный локальный журнал последних 500 событий
state_selected / state_started / state_finished: ID, причина, время, длительность,
предыдущее состояние; для погоды — погодные признаки. Нет ключей, сырых значений
здоровья и сетевых идентификаторов. Снимок здоровья не передаётся серверу.
Production backup отключён. Существующие герои и оплаченные задания не мигрируют
и не очищаются при обновлении.

debounce сети, зарядка, погодная история и разрывы, cooldown, приветствие,

ручного сна, общий fallback после повторного открытия, time-only режим без

окончание одного приветствия, мгновенный переход на home с лоудером и карусель.

кадровый таймер убран для одиночной картинки, полный прогон повторён успешно.

реальных Health Connect разрешений на устройстве пока не проверены без согласия
пользователя. Поведение при отсутствии/частичном доступе покрыто офлайн-тестами
политики разрешений и nullable-снимков; это не замена проверке реального провайдера.
