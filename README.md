# Маскот 3

Отдельное бюджетное Android-приложение с тем же Compose UI, что у `mascot_2`, и строгими словарями, референсами и промптами из `pet_generation_v2.5`.

## Профиль генерации

Версия 0.1.31 переносит проверенный офлайн-флоу в основное приложение: «Постучи» → ожидание → принятие героя → **сразу главный экран**. Открытие экрана создания бесплатно; платная картинка запрашивается после трёх стуков. После явного «ОСТАВИМ» автоматически создаётся **только существующий `greeting`**. Пока видео готовится, на месте персонажа вращается круглый лоудер без глазок, фоновой картинки и скрытого видеоплеера. После сохранения персонаж здоровается, затем остаётся в нейтральной позе, если других видео ещё нет. Остальные 16 анимаций заказываются отдельно (по умолчанию партия 4). При сбое можно продолжить сохранённое задание с прежним токеном или остаться пока без приветствия; новый герой автоматически не создаётся. Имена в заголовках берутся из сохранённых данных и не затираются обновлением DTO.

Задание принятия сохраняется до enqueue в WorkManager: герой, маршрут генерации, submission token и work UUID. Повторный тап и перезапуск UI не создают новую оплату. «Продолжить» после ошибки сохраняет прежний token/provider job ID; неопределённая платная отправка без job ID остаётся заблокированной. Старые герои не получают автоматических платных запросов при обновлении. Для серверного маршрута требуется обновлённый endpoint `POST /v1/mascots/:id/greeting` с `Idempotency-Key`: старый сервер вернёт безопасную ошибку, а не запустит другую анимацию.

- отдельный Android package: `app.mascot3`;
- отдельный backend на Node.js: локально `http://127.0.0.1:8788`, production через HTTPS;
- один фронтальный canonical вместо трёх ракурсов;
- строгий canonical-промпт v2.5 остаётся без изменений;
- платный AI-review canonical отключён, но локальная проверка кадрирования и ручное принятие героя сохранены;
- одна попытка canonical без автоматического платного повтора;
- каталог из 17 анимаций v2.5; при входе переиспользуется сохранённый `greeting`, отдельного платного `welcome` нет; перед «Оживить» пользователь выбирает партию от 1 до числа ещё не готовых, по умолчанию 4;
- `sleep` переиспользуется клиентом как бесплатный `sleep_loop`, без дополнительного запроса к модели;
- video model: `bytedance/seedance-2.0-mini`, 720p, без аудио;
- лимит анимаций: `$9`; общий плановый лимит героя: `$11`.

При текущем профиле видео занимают 112 секунд. Оценка по заложенной в проект ставке `$0.076125/с` — `$8.526` до округления; это расчёт планировщика, не проверка актуального тарифа провайдера. Ещё `$1.75` зарезервировано под lore, character design и canonical image; плановая верхняя оценка героя — `$10.276`, жёсткий общий лимит — `$11`. Лимиты не повышены.

## Безопасность стоимости

Платная генерация героя начинается только после стука в UI. «ОСТАВИМ» подтверждает одно видео-приветствие. Остальные видео запускаются отдельно после выбора количества и подтверждения «Создать». По умолчанию создаются до четырёх отсутствующих анимаций (сначала idle, joyful, sleeping, dancing); «Все» выбирает только оставшиеся. После выбранной партии работа останавливается, другие карточки не попадают в очередь. Прогресс партии и всего каталога показывается отдельно. Точный список сохраняется до запуска, готовые видео пропускаются, сохранённые provider job ID продолжаются без нового POST. В прямом Android-режиме перед каждым платным POST сохраняется отметка отправки: если ответ потерян до записи job ID, автоматический повтор блокируется. Новую попытку в таком случае нужно подтвердить вручную после проверки OpenRouter.

В серверном режиме ключ OpenRouter хранится в server-side `.env`, а API защищён клиентским токеном, дневным лимитом запусков и idempotency key. Текущий командный APK по запросу владельца содержит общий ключ и по умолчанию работает напрямую с OpenRouter; ключ можно извлечь из APK, поэтому сборку нельзя считать защищённым хранилищем секрета. Android также позволяет сохранить собственный ключ. Плановые лимиты стоимости выше относятся к серверному профилю: прямой Android-режим ограничивает число роликов, но не гарантирует жёсткий долларовый лимит.

## Запуск

```bash
npm install
npm start
```

Для production задайте `MASCOT3_DATA_DIR=/data`, `MASCOT3_CLIENT_TOKEN`,
`OPENROUTER_API_KEY` и лимиты из `.env.example`. Каталог `/data` должен быть
persistent volume: в нём атомарно сохраняются библиотека героев, run/job state,
idempotency keys и бюджетный ledger. При первом запуске два проверенных героя
копируются из `deploy/seed`, но существующий volume никогда не перезаписывается.

## Android

Версия 0.1.40 реализует систему поведения по ТЗ v0.3: единый сохранённый resolver
для приложения и виджета, 17 состояний, время/погода/сеть/зарядка, опциональные
сигналы Health Connect, cooldown и приоритеты. Правила и ограничения платформы:
[поведение v0.3](android/STATE_SYSTEM_V0_3.md). Генерационный пайплайн и ранее
сохранённые герои/задания не меняются.

Подписанная релизная сборка 0.1.40 основного приложения: см. [production build](android/PRODUCTION_BUILD.md). Редактирование имени — минималистичное поле без рамки и подложки, с автофокусом и сохранением по галочке или «Готово» на клавиатуре. Нулевой PNG-кадр исключён из анимационных секвенций приложения и виджета; исходные файлы и одиночные превью сохраняются. Новый герой запускается с однократным звуком из `new.wav`: после третьего стука или явного запроса другого героя; без повторов при обновлении экрана, с остановкой при сворачивании и соблюдением беззвучного режима. Иконка заменена на предоставленный `android_app_icon_pack`: растровые ресурсы для пяти плотностей и адаптивная иконка из мастера без дополнительного увеличения рисунка.

Если сохранён только ролик `greeting`, он становится базовым видео главного экрана
и повторяется одним плеером без замены на неподвижный нейтральный кадр. Виджет
также использует его при отсутствии запрошенной анимации и IDLE. После появления
других роликов возвращается обычная логика переключений; готовый IDLE приоритетнее
приветствия как базовый ролик. Это только локальное воспроизведение, без запросов
генерации или изменения сохранённых ассетов.

В прямом режиме OpenRouter новый герой получает имя от отдельного текстового
писателя `openai/gpt-4.1-mini` по сохранённому контракту внешности и характера:
один запрос после сохранения базовой картинки, до экрана «Оставить», максимум
40 выходных токенов и 30 секунд ожидания. Используется тот же выбранный ключ,
что для картинки и видео. Маркер запроса и результат сохраняются до публикации
имени; при неоднозначном обрыве запрос не повторяется, используется локальное
резервное имя. Имя можно изменить вручную; ручная правка всегда приоритетнее
ответа писателя. Старые и импортированные герои автоматически не переименовываются.
Серверный режим сохраняет свой прежний выбор имени из словаря перед лор-писателем.
Доступность модели и формат API сверены по [OpenRouter](https://openrouter.ai/openai/gpt-4.1-mini).
На экране настроений убраны вводные подсказки; при открытом выборе героев цитата
полностью скрыта и возвращается после выбора или закрытия карусели.
Она отключает отладку, сетевые логи, backup и HTTP; подпись постоянным релизным ключом
отличается от старых debug-APK. Не удаляйте старую установку без сохранения героев и заданий.

```bash
./android/gradlew -p android assembleDebug \
  -PMASCOT3_SERVER_URL=https://mascot3.45-91-52-137.sslip.io \
  -PMASCOT3_CLIENT_TOKEN=<beta-client-token>
```

Для физического телефона включите туннель:

```bash
adb reverse tcp:8788 tcp:8788
```

По просьбе владельца командная сборка встраивает общий `OPENROUTER_API_KEY`
из `.env` либо `MASCOT3_OPENROUTER_API_KEY`. Этот ключ можно извлечь из APK:
релиз предназначен для доверенной команды, а не открытого публичного распространения.
В приложении также можно выбрать «Свой OpenRouter» и вставить личный ключ;
пользовательский ключ хранится с помощью Android Keystore. В прямом режиме платные
изображения и видео отправляются с телефона в OpenRouter. При наличии встроенного
ключа первым режимом становится прямой OpenRouter; дальнейший явный выбор режима
сохраняется. Режим командного сервера доступен в настройках.

## Маленький Android-виджет (0.1.26)

Это обычный home-screen AppWidget, без overlay, live wallpaper и новых разрешений.
Уже скачанные видео локально преобразуются в небольшой кэш прозрачных PNG; платные
запросы из виджета не выполняются. Кэш переиспользуется, а пути опубликованных кадров
не меняются при подготовке другой анимации. Запоздавший worker не может подменить
выбранного героя или более новое запрошенное состояние.

One UI использует предзагруженный ViewFlipper с URI кадров. На Android 12+ остальных
лаунчеров используется фиксированная RemoteCollectionItems: нет отдельного обращения
к сервису и декодирования PNG приложением на каждом кадре. Для Android 8–11 сохранён
совместимый сервисный адаптер. Исходящий кадр скрывается сразу, без прозрачного fade,
а неизменившаяся анимация не пересоздаётся при обычном обновлении. При смене источника
используется альтернативный layout, чтобы лаунчер не смешивал старый и новый адаптер.

Для коротких видео целевая частота — около 12 fps; длинные клипы прореживаются до 96
кадров с сохранением общей длительности в пределах половины интервала кадра. Интервалы
83/125/250/500/1000/2000 мс заданы в XML: AdapterViewFlipper не разрешает вызывать
setFlipInterval через RemoteViews. Битмапы фиксированной коллекции ограничены суммарно
6 MiB. Все 17 готовых действий участвуют в ротации, спокойные чаще; ночной/погодный
контекст может фиксировать состояние. Ротация примерно раз в две минуты через
непробуждающий неточный alarm; подготовка нового состояния пропускается при выключенном
экране и в энергосбережении. Это не гарантия нулевого расхода батареи или 24/30 fps:
уже показываемым виджетом управляет лаунчер, его поведение нужно проверять на телефонах.

Загрузка обоих render paths, XML-интервалы, parcel round-trip 96 кадров, инвалидирование
кэша и ротация проверяются без сети на синтетических данных:

```bash
./android/gradlew -p android :app:testDebugUnitTest \
  -PMASCOT3_TEST_JAVA_HOME=/path/to/jdk-21-or-newer
```

## Приветствие при входе (0.1.27, исторически; отдельный welcome отменён в 0.1.29)

`welcome` — отдельный шестисекундный ролик: заметить пользователя, поднять одну уже
существующую свободную руку/лапу, приветливо помахать два раза, опустить её и вернуться
в исходную позу. Весь жест остаётся внутри безопасного кадрирования. Если свободной
руки/лапы нет, персонаж кивает, не меняя анатомию и не роняя предметы. Прямой Android
промпт и серверный каталог содержат это действие отдельно от общего `greeting`.

Один готовый ролик проигрывается при первом открытии и настоящем возвращении приложения
на передний план. Возврат из меню, recomposition и поворот экрана не создают новое
событие. Тап/свайп прерывает `welcome`, после завершения он уступает место idle.
В случайную колоду и ротацию виджета `welcome` не входит. Если новый ролик отсутствует,
можно воспроизвести сохранённый `greeting`; если отсутствуют оба, приветствие пропускается.
Открытие приложения не генерирует недостающие ролики. По умолчанию партия по-прежнему 4;
пользователь может выбрать до всех оставшихся 18. После четырёх основных действий
`welcome` идёт первым среди новых, поэтому при отсутствии незавершённых заданий партия
из одного создаст именно приветствие без заказа всего каталога. Полный старый набор из 17 позволяет
догенерировать только `welcome` через явное подтверждение партии, не повторяя готовые.
Старые worker'ы без списка действий сохраняют прежнюю авторизацию на 17; обновление
не добавляет новый платный POST к ранее запущенной партии. Новая серверная поддержка
требует отдельного deployment; изменение исходников не обновляет production автоматически.
Серверный CLI разрешает продолжить batch каталога v44 на v45 только при точном совпадении
всех прежних промптов, длительностей, source hash и общего кадрирования; список партии
и её исходная версия сохраняются. Произвольные изменения каталога по-прежнему блокируют resume.

## Общая библиотека: Уна (0.1.28)

Командный APK содержит Уну (`716cdb43-703b-4d7e-8a79-27f03d92b99c`) рядом с двумя
прежними встроенными героями. Имя, прозрачная базовая картинка, 17 оригинальных MP4,
технический цвет фона, контракт персонажа и записи QA/стоимости перенесены без
изменения содержимого. Старый кэш виджета не включён: текущая версия готовит его
из локальных видео по своему формату, без обращения к моделям. Отдельного `welcome`
в выгрузке нет; при входе можно проиграть уже готовый `greeting`.

Импорт выполняется на IO-потоке перед чтением библиотеки. Копируются только
отсутствующие файлы, через временный файл и публикацию без перезаписи; `base.png`
публикуется последним, чтобы незавершённый новый герой не появлялся в списке.
После обрыва копирование продолжается при следующем открытии. Существующие герои,
пользовательские имена, ролики и выбранный герой сохраняются. Импорт не создаёт
provider jobs, не запускает генерацию и не загружает героя в командный сервер.

## Детализация виджета и 17 действий (0.1.29)

Кэш v4 содержит кадры до 320 px вместо 160. Число кадров и интервалы не урезаны:
для URI-предзагрузки весь набор сырых ARGB-пикселей ограничен 24 MiB, что даёт
256–320 px в зависимости от длины ролика. Inline-коллекции Pixel/AOSP по-прежнему
ограничены прежними 6 MiB; увеличение разрешения для них не обходится повышением
лимита памяти. Это бюджеты самих пикселей одного клипа, не гарантия общей памяти
лаунчера или нулевого расхода батареи.

По всем выбранным кадрам рассчитывается один центрированный crop с запасом:
лишние прозрачные поля убраны, камера не следует за движением и не меняет масштаб
между кадрами. Окно сохраняет не менее 60% исходного полотна и пропорции; при
размашистом движении автоматически расширяется вплоть до всего исходного кадра.
Chroma-key выполняется до финального уменьшения с фильтрацией прозрачных пикселей.
Для обычных исходных видео используется полное разрешение; сверхкрупные видео
на Android 8.1+ ограничиваются 1280 px на этапе обработки, чтобы ограничить пик RAM.
Подготовка выполняется локально один раз на новый источник/версию кэша. Старый v3
остаётся доступен лаунчеру во время подготовки; новые пути публикуются только после
завершения, тёплый v4 не открывает декодер. Платных запросов нет.

Отдельное действие `welcome` удалено из UI и новых партий. При входе один раз
проигрывается прежний `greeting`, если он уже сохранён; отсутствие ролика ничего
не генерирует. Готовый старый каталог снова считается полным при 17 роликах.
Android-resume исключает `welcome` из старого списка, не расширяя оставшуюся партию.
Платные результаты и provider ID не удаляются. Серверный legacy batch с недостающими
действиями и `welcome` требует ручной сверки вместо создания нового платного batch.
Catalog v46 разрешает resume неизменённых наборов из 17 от v44/v45 только при
совпадении полного прежнего render hash; версии с `welcome` блокируются безопасно.
Серверные исходники обновлены, production автоматически не переустанавливался.

## Rollback и данные

Откат к предыдущему image выполняется только для ресурса Mascot 3 в Coolify.
Persistent volume `/data` не удаляется и не откатывается вместе с кодом. Перед
изменением формата данных требуется отдельная миграция и резервная копия.
